# arboretum

English · [简体中文](README.zh-CN.md)

**Deterministic derivatives pricing that runs on-chain, in Rust, with no floating point anywhere.**

An option price is normally a number somebody else computed off-chain and fed to your
contract through an oracle. This makes it a number anyone can recompute: given the same
six inputs, every validator executes the same integer arithmetic and reaches the same
answer, bit for bit.

## Why on-chain, and where that stops being true

The honest version of the pitch is narrower than "cheaper" or "faster", and it is
narrower on purpose.

Today's on-chain options protocols get their mark price from an off-chain model. That
means the number driving your liquidation and your settlement comes from a computation
you cannot inspect or reproduce; the chain only executes the assertion. Moving the
computation on-chain turns the price into something a third party can re-derive from
public inputs with the same program.

That property costs one to two orders of magnitude more gas than trusting an oracle, so it
belongs where the stakes justify it: **settlement and expiry prices, fallback marks,
reproducible audit, and structured-product construction** — once per market, high value,
adversarial. Streaming quotes should stay off-chain. This crate is not trying to compete
with a market maker.

## Usage

```bash
cargo test                          # 36 tests across the host crates
cargo clippy --all-targets          # clean
cargo run -p arbreport              # regenerate docs/ACCURACY.md
py reference/gen_vectors.py         # regenerate reference vectors (Python 3)

cd crates/arbcontract               # the contract is its own workspace: wasm only
cargo build --release --target wasm32-unknown-unknown --lib
cd ../..

scripts/size.sh                     # raw and brotli size, contract and kernel
scripts/verify_no_floats.sh         # validate + disassemble, fail on any f32/f64
```

Note on the layout: `arbcontract` is excluded from the root workspace and carries its own
`[profile.release]`. Linking it for the host fails by design, and inheriting the host
profile would cost roughly a third of the artifact size.

The `--lib` is not decoration. The package also has a bin target, the constructor probe,
and both write to the same `arbcontract.wasm` path, so building without a target leaves
whichever finished last sitting there, and the bin is 368 bytes. A size check or a
no-floating-point check run against that stub would pass while proving nothing. Both
scripts now ask for the lib by name, and `verify_no_floats.sh` refuses any module that does
not export `user_entrypoint`.

```rust
use arbnum::D;
use arbpricing::{european, greeks, binomial, implied_vol, bounds, Kind, Market};

// 250 spot, 240 strike, 3 months, 35% vol, 5% rate, 1% carry — all at 1e9 scale.
let m = Market {
    spot: D::from_raw(250_000_000_000),
    strike: D::from_raw(240_000_000_000),
    t: D::from_raw(250_000_000),       // 0.25 years
    sigma: D::from_raw(350_000_000),
    rate: D::from_raw(50_000_000),
    carry: D::from_raw(10_000_000),
};
let call = european(&m, Kind::Call)?;
let american = binomial(&m, Kind::Put, 512, true)?;
let vol = implied_vol(call, m, Kind::Call)?;
```

## The demo page

**Live at <https://arboretum-pricing-vkk9ilpssgw.qoder.zone>**, and it needs no wallet.

`web/` is a Next.js app that lets a reviewer verify the whole claim without trusting any
part of our stack: pick an option, the page asks the deployed contract, and it shows the
answer next to the same case priced by this repository's Rust build. A MATCH badge means the
two integers are equal with no tolerance applied.

It contains no pricing code of its own, on purpose. A JavaScript reimplementation would be a
second, floating-point answer to a question whose only interesting property is that it has
exactly one answer, so the host side ships as data generated by
`scripts/gen_parity.sh` (1680 European cases plus the lattice panel's fixed selection).

The page also prints the exact calldata of the call it made, so the same value can be
fetched with `eth_call` from any node.

```bash
cd web && npm install && npm run dev     # http://localhost:3000
```

Reads go straight from the browser to a public Arbitrum Sepolia RPC, with a fallback
transport across three independent endpoints: the official one is served through a load
balancer whose backends sometimes repeat the `access-control-allow-origin` header, which
browsers reject. It builds to a static export, so there is no server of ours in the path.

## What is actually guaranteed

**No floating point.** Arbitrum's Stylus runtime lists `f32`/`f64` as unsupported
(<https://docs.arbitrum.io/stylus/concepts/webassembly>), so the engine is written in
signed fixed point at 1e9 (`i128`) with an explicit round-half-up rule. Floats appear only
in `#[cfg(test)]` code and in the host-only `arbreport` binary; neither can reach a
validator. This is what makes the result reproducible rather than merely
deterministic-looking, and `scripts/verify_no_floats.sh` checks it against the compiled
artifact rather than the source.

**Bounded, checked arithmetic.** Every operation is checked. Overflow is an error, never a
wraparound. A product that will not fit takes a split path; if it still will not fit, the
call reverts with a reason.

**No third-party dependencies.** Nothing is pulled from crates.io: the elementary
functions are implemented here, both for auditability and because the Stylus code-size
limit punishes pulling in a general-purpose math crate. `exp`, `ln`, `sqrt`, `pow`, `erf`,
`norm_cdf` and `norm_pdf` are all hand-written series or rational forms.

**Accuracy is measured, not asserted.** 3336 reference cases from CPython's `math` module,
with every reference evaluated at the quantised input so that what is measured is
approximation error rather than input rounding. Budgets are *derived* — the price budget
is the normal CDF's published error propagated through the two terms of the formula, not a
convenient constant.

| group | cases | measured |
|---|---:|---|
| `exp` | 276 | 2.2e-9 relative |
| `ln` | 300 | 1.7e-8 relative |
| `sqrt` | 300 | 7.0e-7 relative |
| `Phi` | 560 | 7.55e-8 absolute |
| Black-Scholes + Greeks | 1480 | within derived band on every case |
| CRR lattice (Euro + American) | 10 | 1.4e-6 relative |
| implied volatility | 10 | 8.0e-6 on sigma |

## Size

Stylus limits the **compressed** program size. `scripts/size.sh` measures it, and the
official CLI measures it after `wasm-opt`, which is smaller:

| artifact | raw | brotli -q11 | official |
|---|---:|---:|---:|
| `arbcontract` — the contract, every pricing path exposed | 69.5 KB | 18.4 KB | **14,668 bytes** |
| `arbwasm` — the kernel alone, for attribution | 48.2 KB | 14.6 KB | — |

Limit: 96 KB (ArbOS Elara, 2026-08-20), 24 KB before it. Both artifacts fit under the
pre-Elara limit too, which means the engine is deployable on chains that have not taken
that upgrade.

**The deployed contract and a local build of this source agree bit for bit.**

That is the thesis of the project stated as a command anyone can run: not "trust the
number", but "run the program and get the same number". Deploying it needs a funded key and
six separate pieces of tooling configuration, all documented in
[`docs/DEPLOY.md`](docs/DEPLOY.md) — including the one-file patch the official CLI needs to
build on Windows at all.

`scripts/verify_no_floats.sh` validates the compiled module and disassembles it: every
float-typed value in WebAssembly spells `f32` or `f64` in the text form, so the "no
floating point" claim is checked against the artifact rather than asserted from the source.

## Known limitations

Stated plainly, because a project that hides its limits is less trustworthy than one that
names them.

1. **Volatility is an input, and there is no live implied-volatility surface for
   tokenised equities to read.** The contribution is the deterministic transform from
   inputs to price, not the data source. Published vol surfaces belong behind a signed or
   Merkle-committed input, which is designed for but not built.
2. **The normal CDF uses Abramowitz & Stegun 26.2.17** (published 7.5e-8 absolute, measured
   7.55e-8 here). It is accurate to about two thousandths of a basis point on a $250
   underlying. It is not correctly rounded, and monotonicity in volatility is only
   asserted to within that error, not exactly.
3. **Deep out-of-the-money premiums below ~1e-9 flush to zero.** The closed form is a
   difference of two terms that cancel there; the engine detects the cancellation and
   floors at zero rather than returning noise, and the noise band that width is derived
   from the CDF error.
4. **No jump-diffusion, stochastic-volatility, or barrier models.** This is the
   Black-Scholes and CRR family, priced carefully, not a model suite.
5. **Not audited.** The contract runs on Arbitrum Sepolia. It is not on a mainnet, and no
   external review has been done.

## Prior art

Three things make a claim of priority false, so none is made:

- **Lyra's first version ran Black-Scholes inside the contract.** On-chain pricing is not
  new.
- **Offchain Labs demoed Black-Scholes in Stylus in October 2024** (Stylus Pro Series,
  Day 3), which is listed in their own `awesome-stylus`. "First Black-Scholes in Stylus" is
  therefore also false.
- **`chrisco512/black_scholes`** (October 2024) is the closest public repository: European
  pricing only, built on `rust_decimal` rather than integer fixed point, never deployed, no
  demonstration page.

Within this same buildathon there is also **`afterhours`** (September 2026), a Stylus
contract that prices a put and wraps an ERC-4626 vault.

What is not covered by any of them, and what this repository does: closed form, five Greeks,
CRR lattices with early exercise, implied-volatility inversion and a derived uncertainty
band together; pure integer arithmetic, with the absence of floating point verified against
the compiled artifact rather than the source; a deployed contract checked entry point by
entry point against a local build; and the accuracy harness that produces its own numbers.
